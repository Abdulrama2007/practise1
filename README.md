# Эмулятор UNIX-оболочки: вариант 21

Практическая работа по конфигурационному управлению, ИКБО-18-25.
Язык: Python 3.10+. Зависимости: только стандартная библиотека.

## Что делает программа

Программа имитирует UNIX-терминал в графическом окне tkinter.
Заголовок содержит настоящие имя пользователя и имя компьютера.
Все файлы и папки виртуальные: XML загружается в дерево объектов в памяти.
Команды эмулятора не передаются оболочке настоящей ОС.
Пять этапов разработки сохранены отдельными Git-коммитами.

## Быстрый запуск в Windows

1. Установите Python версии 3.10 или новее с компонентом Tcl/Tk.
   Если пользуетесь командой `python`, добавьте Python в PATH.
2. Распакуйте весь архив, сохранив структуру папок.
3. Откройте `demo.bat` двойным щелчком: появится терминал с примером.
4. Введите `pwd`, `ls`, `cd /home/student`, `du -s /`.
5. Команда `exit` закрывает окно.

`start.bat` открывает окно с VFS по умолчанию без сценария.
`run.bat` — служебный запуск с передачей параметров, без паузы при ошибке.
`test.bat` запускает автоматические проверки и оставляет результат на экране.
Сборка и установка pip-пакетов не требуются.

## Запуск из командной строки

Все команды выполняются из папки проекта.

```text
python -m src.main
python -m src.main --vfs examples/deep.xml
python -m src.main --vfs examples/deep.xml --startup examples/demo.txt
python -m src.main --headless --vfs examples/deep.xml --startup examples/demo.txt
python -m unittest discover -s tests -v
```

В Windows вместо `python` можно использовать `py -3`.
Linux/macOS: используйте `python3`; запуск также через `sh demo.sh`.
В Linux tkinter может требовать системный пакет `python3-tk`.

## Настройки

| Параметр | Назначение |
| --- | --- |
| `--vfs ПУТЬ` | Исходный XML-файл виртуальной файловой системы |
| `--startup ПУТЬ` | Файл с командами эмулятора в UTF-8 или UTF-8 BOM |
| `--headless` | Дополнительный режим проверки без GUI |
| `--help` | Справка о параметрах |

Пути к физическим файлам отсчитываются от папки запуска.
Путь с пробелами в параметрах запуска нужно заключать в кавычки.
Все настройки выводятся при старте в консоль и журнал окна.
Без `--vfs` создаётся VFS по умолчанию в памяти:
папки `/home`, `/empty` и файл `/home/readme.txt`.
Если заданный XML отсутствует или некорректен, программа сообщает об ошибке
и завершается. Без стартового скрипта GUI ожидает ручного ввода.
В режиме `--headless` без скрипта команды читаются из стандартного ввода.

## Команды и поддерживаемые режимы

| Команда | Действие |
| --- | --- |
| `ls [путь]` | Список содержимого папки или имя указанного файла |
| `ls -a [путь]` | То же, включая имена, начинающиеся с точки |
| `cd [путь]` | Переход в папку; без аргументов — в корень `/` |
| `pwd` | Текущий абсолютный виртуальный путь |
| `du [путь]` | Размер вложенных папок и общий размер выбранного объекта |
| `du -s [путь]` | Только итоговый размер выбранного объекта |
| `rmdir путь` | Удаление одной пустой папки из памяти |
| `vfs-init` | Замена VFS на состояние по умолчанию |
| `exit` | Завершение сеанса и закрытие окна |

`ls` и `du` без пути работают с текущей папкой.
Имена выводятся в отсортированном порядке; папки отмечаются `/`.
Пути поддерживают `/`, `.`, `..`, повторяющиеся разделители и русские имена.
Команда `cd ..` в корне остаётся в корне.
Переход через отсутствующую папку или файл возвращает ошибку.

**du показывает байты содержимого виртуальных файлов**, включая декодированный
base64. Это не размер XML-файла и не количество блоков настоящего диска.
Папка занимает сумму размеров всех вложенных файлов; пустая папка — 0 байтов.
Скрытые файлы учитываются в размере. Текст хранится в UTF-8, поэтому русская
буква обычно занимает больше одного байта. Вывод: `размер<TAB>путь`.

`rmdir` отклоняет файлы, непустые папки, корень и текущую папку.
Несколько путей и флаг `-p` не поддерживаются.
При ошибке команда не меняет состояние; сеанс продолжается.

### Особенность vfs-init

По условию этот служебный сброс очищает также физическое представление VFS.
В проекте это означает замену исходного XML новым корректным XML с деревом
по умолчанию. Запись атомарная: сначала временный файл рядом с исходным,
затем замена XML. При ошибке записи состояние памяти остаётся прежним.
Без `--vfs` сброс выполняется только в памяти, на диск ничего не записывается.
Обычные команды, включая `rmdir`, **никогда не сохраняют изменения в XML**.

`demo.bat` и проверочные скрипты создают рабочие копии в `runtime/`,
поэтому исходные примеры в `examples/` сохраняются.

## Формат XML

Корень — `<vfs name="...">`; внутри — `<directory>` и `<file>`.
Атрибут `name` обязателен для каждой папки и файла.
В папке имена не должны повторяться. Имена `.` и `..`, пробелы,
символы `/` и `\` внутри имён запрещены.

```xml
<?xml version="1.0" encoding="utf-8"?>
<vfs name="example">
  <directory name="documents">
    <file name="hello.txt" encoding="utf-8">Привет!</file>
    <file name="data.bin" encoding="base64">AAECAw==</file>
    <directory name="empty" />
  </directory>
</vfs>
```

Если `encoding` не указан, используется UTF-8.
Для base64 допустимы пробелы и переносы; неверные данные возвращают ошибку.
XML-разметка в текстовом содержимом экранируется, например `&amp;`.
Файлы внутри VFS не распаковываются в реальные папки.

## Стартовые и проверочные скрипты

Файл сценария содержит одну команду на строку. Пустые строки и строки,
начинающиеся с `#`, пропускаются. Выводятся и команда, и её ответ.
После ошибочной команды выполняется следующая строка.
После `exit` оставшиеся строки не выполняются.
Парсер команд разделяет ввод по пробелам, как требует вариант 21.
Кавычки внутри команд эмулятора не обрабатываются.

| Файл | Назначение |
| --- | --- |
| `examples/demo.txt` | Краткая успешная демонстрация; окно остаётся открытым |
| `examples/stage1.txt` | Команды для ручной демонстрации первого этапа |
| `examples/stage2.txt` | Последовательный запуск и продолжение после ошибок |
| `examples/stage3.txt` | Сброс VFS и обработка ошибок |
| `examples/stage4.txt` | Все режимы ls, cd, pwd, du и ошибки |
| `examples/stage5.txt` | Удаление папок и ошибки rmdir |
| `examples/all_commands.txt` | Полная проверка всех команд, сброса и exit |
| `examples/minimal.xml` | Минимальное пустое дерево |
| `examples/multiple.xml` | Несколько файлов, включая двоичный |
| `examples/deep.xml` | Более трёх уровней вложенности |
| `examples/invalid.xml` | Намеренно некорректный XML для проверки ошибки |

Первый этап ещё не поддерживает стартовые скрипты: его демонстрируют вручную.
Файл `stage1.txt` используется как список команд для ручного ввода.

В `scripts/` находятся три пары скриптов реальной ОС `.bat` и `.sh`:
`test_config`, `test_vfs`, `test_commands`.
Они запускают разные сочетания параметров, структуры VFS и сценарии.
Например, `sh scripts/test_vfs.sh` или `scripts\test_vfs.bat`.
Некоторые сценарии намеренно ошибочные: сообщения `Ошибка:` там ожидаются.
В headless-режиме код 0 означает отсутствие ошибок, код 1 — ошибки команд,
сценария или VFS, код 2 — ошибка параметров argparse.
GUI после ошибки команды продолжает работу.

## Структура и функции

| Модуль | Назначение |
| --- | --- |
| `src/main.py` | main читает параметры; run_gui открывает окно |
| `src/config.py` | parse_args читает флаги; describe_config описывает настройки |
| `src/gui.py` | Terminal строит окно, показывает диалог и принимает Enter |
| `src/shell.py` | Shell.execute разбирает и выполняет строку команды |
| `src/commands.py` | Обработчики команд и проверки аргументов |
| `src/vfs.py` | Node — узел; VFS — дерево, загрузка, поиск пути и сброс |
| `src/xml_format.py` | Проверка имён, UTF-8/base64, сериализация дерева |
| `src/startup.py` | run_script читает файл; execute_lines выполняет строки |
| `tests/` | unittest-проверки команд, XML, ошибок и реального процесса CLI |

Внутри VFS хранится `root` — корневой узел и `cwd` — текущий путь.
У Node есть имя, признак папки, словарь дочерних узлов и байты файла.
`VFS.resolve` проходит дерево и возвращает узел и абсолютный путь.
`Node.size` рекурсивно суммирует длины содержимого файлов.
`VFS.reset` создаёт исходное дерево; `atomic_write` заменяет его XML.
Документация функций также находится в их docstring.

## Тесты

```text
python -m unittest discover -s tests -v
```

Проверяются разбор команды, неверные аргументы, последовательность скрипта,
UTF-8 BOM, base64, вложенность и пути, размеры файлов, сохранность XML,
удаление папок, сброс на диске и поведение при ошибке записи.
Интеграционные проверки запускают `python -m src.main` отдельным процессом.
Обработчики GUI проверяются с заменёнными виджетами и настоящей оболочкой.
В среде подготовки нет графического дисплея: визуальная проверка окна
и запуск Windows .bat здесь не выполнялись. Для проверки на Windows
откройте demo.bat и выполните последовательность из DEFENSE.md.

## Git и сдача

В архиве сохранена папка `.git` с пятью коммитами разработки.
Автор коммитов — техническая подпись Project Author.
Репозиторий пока локальный: для сдачи его нужно опубликовать.
Проверьте историю командой `git log --oneline --reverse`.

1. Создайте пустой публичный репозиторий на разрешённом Git-сервисе.
   Не добавляйте туда README или другие файлы через сайт.
2. В терминале из папки проекта выполните команды, подставив свой адрес:

```text
git remote add origin АДРЕС_ВАШЕГО_РЕПОЗИТОРИЯ
git push -u origin main
```

Не загружайте ZIP в репозиторий: публикуется распакованный проект.
Не добавляйте `runtime/`, служебные файлы Python или настройки редактора.
Они перечислены в `.gitignore`.
Если Windows скрывает `.git`, включите показ скрытых элементов.

Порядок этапов: GUI-прототип → настройки и скрипты → XML VFS →
основные команды → rmdir, проверки и документация.
Для первого этапа были заглушки ls/cd; в итоговой версии они полноценные.
На защите показывают работу программы и объясняют каждый этап.
Для подготовки используйте `DEFENSE.md`.
